# Надёжная синхронизация операторского ПК с NAS

## Граница ответственности

- PostgreSQL на NAS — единственный источник истины для карточек и результатов.
- MinIO на NAS — долговременное хранилище моделей и вложений.
- `nas-sync` запускается на каждом операторском ПК и только передаёт файлы.
  Он не парсит логи, не режет STL, не запускает математику или ML.
- Локальная очередь находится в `OPERATOR_STATE_HOST_PATH/nas-outbox`. Эту
  папку нельзя размещать на NAS или одновременно подключать к двум ПК.

## Протокол публикации вложения

1. API потоково принимает файл во временный файл и рассчитывает SHA-256.
2. Файл повторно копируется в локальный outbox с одновременной проверкой
   размера и SHA-256. Только полностью записанный каталог атомарно появляется
   в состоянии `pending`.
3. MinIO получает файл по неизменяемому ключу, содержащему идентификатор
   операции и полный SHA-256. Завершённый PUT виден атомарно; после него
   проверяются размер и сохранённая SHA-256 metadata.
4. Только после проверки объекта создаётся ссылка в PostgreSQL. Уникальный
   индекс `(record_id, checksum)` выбирает одного победителя, если одинаковые
   байты одновременно отправили несколько ПК.
5. После commit локальный большой payload удаляется, остаётся маленькая
   квитанция. Если процесс завершился между шагами, повтор безопасен.

Долгая передача не держит соединение PostgreSQL. При пустой очереди `nas-sync`
не опрашивает NAS вообще, поэтому слабый NAS не получает фоновую нагрузку.

## Поведение при сбоях

- MinIO или PostgreSQL недоступны: API отвечает `202`, а файл остаётся
  локально и отправляется автоматически с экспоненциальной задержкой.
- API/контейнер/ПК перезапущен: незавершённая локальная аренда истекает, после
  чего операция снова переходит в `pending`.
- Одинаковый файл отправлен повторно: локальный operation id и уникальность в
  PostgreSQL исключают вторую запись.
- Карточка удалена или STL оказался в очереди не ПК-владельца: операция
  переводится в `failed`, файл не теряется и ждёт решения оператора.
- Локальный файл изменился/повреждён: публикация блокируется по SHA-256.
- Очередь достигла `NAS_OUTBOX_MAX_BYTES`: новая загрузка получает `507`; уже
  принятые файлы не удаляются.
- Загруженные журналы сначала остаются в локальной папке оператора. До разбора
  исходный пакет публикуется в MinIO по ключам с SHA-256 и проверяется после
  записи. При недоступности NAS локальная задача откладывается с ограниченной
  экспоненциальной задержкой без терминального лимита попыток.

Состояние доступно без обращения к NAS:

```text
GET  /sync/status
GET  /sync/operations/{operation_id}
POST /sync/operations/{operation_id}/retry
```

Последний запрос вручную возвращает исправленную операцию из `failed` в
`pending`. До повтора нужно устранить причину конфликта.

## Логи и результаты расчётов

- Браузерные логи сначала целиком сохраняются в локальную входящую папку ПК.
  Локальный `worker` публикует исходники в MinIO по неизменяемым ключам с
  SHA-256 и только после этого начинает разбор. Поэтому NAS не получает задачу
  анализа и не расходует процессор на вычисления.
- Расчётный результат не передаётся как отдельный файл outbox. Сама задача уже
  долговечно записана в PostgreSQL с ключом идемпотентности, владельцем ПК и
  ограждённой арендой. При обрыве базы частичный результат не публикуется;
  после восстановления тот же ПК забирает задачу повторно. Это может повторить
  локальный расчёт, но не создаёт две конкурирующие версии результата.
- Карточки не редактируются офлайн и затем не «сливаются». Для полей карточки
  PostgreSQL остаётся единственным источником истины, а проверка `revision`
  явно сообщает оператору о параллельном изменении с другого ПК.

## Настройки

| Переменная | Значение по умолчанию в Docker | Назначение |
|---|---:|---|
| `NAS_OUTBOX_PATH` | `/var/lib/printer-companion/nas-outbox` | локальная постоянная очередь |
| `NAS_OUTBOX_MAX_BYTES` | `21474836480` | максимум 20 ГБ ожидающих payload |
| `NAS_SYNC_POLL_SECONDS` | `2` | проверка локальной очереди, не NAS |
| `NAS_SYNC_RETRY_MIN_SECONDS` | `5` | первая задержка повтора |
| `NAS_SYNC_RETRY_MAX_SECONDS` | `300` | максимальная задержка повтора |
| `NAS_SYNC_CLAIM_SECONDS` | `900` | восстановление после падения процесса |

Свободное место в `OPERATOR_STATE_HOST_PATH` нужно мониторить и резервировать с
учётом максимального размера одновременно загружаемых STL. Локальный outbox —
страховка передачи, а не резервная копия NAS.
