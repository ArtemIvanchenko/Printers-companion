# Проверка времени из логов — 9 сентября 2026

## Реальные исходники

Проверены семь указанных оператором каталогов рабочего стола. Найдено 30
`*_time.log`, из них 14 уникальных по SHA-256. Три уникальных файла содержат
только заголовок. Флешка в момент проверки не смонтирована; её новые данные
в эту проверку не входят.

В непустых файлах — 16 639 summary и столько же detailed-записей. Все пары
соседние, все три длительности согласуются с абсолютными счётчиками в пределах
20 мс или 1%. Потерь summary при разборе и физически невозможных циклов нет.
Это подтверждает чтение длительностей, но не доказывает точность прогноза
новой модели или соответствие файла конкретной карточке.

Повторы: одна эквивалентная копия и 39 отличающихся повторных записей. После
проверок доступно 16 559 слоёв для калибровки в сумме по уникальным файлам.
Это не число уникальных печатей: межфайловое сопоставление сессий здесь не
проводилось. Полный машиночитаемый результат: `2026-09-09_time_log_audit.json`.

## Исправления

1. Summary и detailed теперь связываются по соседству и номеру слоя. Прежний
   `zip` списков по номеру слоя сдвигал проверку при утраченной строке перед
   повторной попыткой. Добавлены число непарных записей и статус сверки.
2. Значения с мусором после цифр, отрицательные абсолютные счётчики и повтор
   одного ключа внутри detailed больше не принимаются как корректные числа.
3. Противоречие с абсолютными счётчиками помечает summary как
   `timing_valid=false`. Исходное событие остаётся доступным для диагностики,
   но исключается из калибровки и из сводки `timing_evidence`.
4. Общий отбор `timing_validation.py` исключает конфликтующий физический слой
   до проверки отдельных диапазонов. Раньше повтор с недопустимым временем
   мог исчезнуть при фильтрации, оставив первую попытку как нормальное измерение.
5. Хранение и чтение исходных файлов используют общий отбор; при чтении все
   суточные файлы рассматриваются вместе. Конфликт только в нанесении порошка
   или полном цикле теперь исключает слой и из калибровки прожига.
6. Добавлена защита от NaN, бесконечности, логических значений и некорректного
   номера слоя. Обновлены версии парсера (0.5.0) и аналитики (0.3.2).

Нормальное машинное время по-прежнему отделено от пауз. Алгоритм минимального
цикла и его робастной калибровки в этой итерации не изменялся. Два старых тестовых
примера содержали полный цикл короче суммы компонентов; генератор тестовых
логов исправлен, чтобы проверять калибровку на физически согласованных данных.

## Воспроизведение

```bash
python -m scripts.research.audit_time_logs /путь/к/логам --output audit.json
APP_ENV=test DATABASE_URL=sqlite:////tmp/отдельная-тестовая-база.sqlite pytest -q
ruff check .
```

Для проверки миграций использована другая чистая временная SQLite БД:
`alembic upgrade head`, затем `scripts/check_migration_drift.py`. Схема совпала
с ORM, Ruff и проверка пробельных ошибок прошли.
Полный тестовый прогон: **731 passed**, 28,33 с. При первом запуске без
`APP_ENV=test` шесть интеграционных проверок ожидали тестовый режим очередей
и хранилища; после запуска с настройками из CI все прошли.

Рабочая БД и сохранённые калибровки не пересчитаны. Новые правила действуют при
следующем разборе/переимпорте. Старые сохранённые слои без этих метаданных не
считаются автоматически повторно проверенными.

## Граница этой итерации

Ещё требуется отдельная проверка статистики фаз и обзорной телеметрии:
`analytics/phase_statistics.py` и `domain/services/session_overview.py` имеют
собственную обработку первых повторов и fallback по абсолютным маркерам.
Не считать их эквивалентными исправленному пути калибровки. Также назначение
части каналов Monitor и единицы расхода газа остаются неподтверждёнными.
