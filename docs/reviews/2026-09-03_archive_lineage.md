# Проверка происхождения подтверждённых логов и моделей — 2026-09-03

## Результат

Проверены восемь папок из `Подтверждённые печати` против шести исходных
архивов, указанных оператором. Сравнение выполнялось по размеру и полному
SHA-256, а не по имени файла. Поэтому переименование и различия Unicode в
русских именах не влияли на результат.

- Найдены точные источники для 8 из 8 файлов Magics.
- Найдены точные источники для 82 из 82 STL-файлов.
- Найдены точные источники для 11 из 11 содержательных `*_time.log`.
- Все 95 из 95 журналов в подтверждённых папках имеют точную одноимённую копию
  в исходной папке `Логи`.
- Оставшиеся восемь `*_time.log` в папке `Логи` не содержат измерений: три
  пустые, четыре содержат только один 44-байтный заголовок, один содержит семь
  повторов заголовка. Их нельзя использовать как наблюдения времени печати.

## Варианты M350 и данные без подтверждённой пары

`M350 Logs (1)` почти полностью является копией `M350 Logs`: 14 из 15 файлов
совпадают по SHA-256. Единственное отличие — `09.06.2026_sensors.log`: файл из
`M350 Logs (1)` является точным более коротким префиксом версии из `M350 Logs`.

Для 09.06 обнаружена цепочка append-only снимков:

- `M350 Logs (1)/09.06.2026_sensors.log` — 122 421 248 байт;
- `Логи/09.06.2026_sensors.log` — 131 211 020 байт;
- `M350 Logs/09.06.2026_sensors.log` — 133 184 492 байта.

Каждый меньший файл побайтно является префиксом следующего. Аналогично
`Логи/09.06.2026_stateFlow.log` (1 222 639 616 байт) является точным префиксом
версии из `M350 Logs` (1 240 947 338 байт). Поэтому эти файлы нельзя объявлять
разными сессиями только из-за разных SHA-256: это версии одного растущего лога.
Для неизменяемого архива следует хранить оба хеша и отношение `supersedes`, а
для аналитики выбирать наиболее полный проверенный снимок.

В основной папке M350 остаются 22 файла без копии в `Логи`: пары sensor/stateFlow
за 15 и 17 июня, а также 3, 6, 7, 9, 10, 13, 14, 17 и 18 июля. У них нет
`*_time.log` в предоставленном архиве. По одному лишь совпадению даты связывать
их с Magics нельзя. Возможные июльские кандидаты существуют, но должны остаться
ручными кандидатами до появления журнала слоёв, карточки или подтверждения
оператора. `17.06.2026_stateFlow.log` имеет нулевой размер и доказательством
связи не является.

Не вошли в подтверждённый набор:

- 24 из 26 Magics и 178 из 179 STL в `Модели под печать 1 авг`;
- все 12 Magics и 12 STL в `Расчет моделек для Яковлева`;
- 14 из 20 Magics и 209 из 289 STL в `Все печати`.

Это не означает, что файлы ошибочны: среди них есть заготовки, альтернативные
компоновки, отдельные детали, поддержки и будущие печати. Их нельзя считать
фактически напечатанными без независимого подтверждения.

## Ограничения и правило связывания

SHA-256 подтверждает идентичность файлов, но не причинную связь «этой моделью
напечатан этот лог». Автоматическая связь допустима только при сочетании
нескольких признаков: подтверждённый импорт оператором или хеш компоновки,
совместимое число слоёв/высота, материал и режим. Совпадение фактической
длительности с текущим прогнозом использовать для выбора пары нельзя — это
круговая утечка. Дата и имя файла сами по себе дают только кандидата.

Проверку можно повторить без изменения исходных архивов:

```bash
python scripts/research/audit_archive_lineage.py \
  CONFIRMED_ROOT SOURCE_ROOT_1 SOURCE_ROOT_2 --format json

python scripts/research/audit_archive_lineage.py \
  CONFIRMED_ROOT SOURCE_ROOT_1 SOURCE_ROOT_2 --include-all-logs --format json
```

По умолчанию проверяются Magics, STL и `*_time.log`. Второй режим добавляет все
логи и ищет более новые/старые append-only снимки только при одинаковом имени и
совпадении как минимум первых 4096 байт. Пустые файлы не считаются префиксным
доказательством.
