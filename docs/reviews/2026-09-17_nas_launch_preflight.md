# Проверка установки NAS до следующей попытки запуска

Дата: 17 сентября 2026. Проверенный checkout: `d2cb6a3`.

## Границы проверки

Скриншоты пользователя получены с другого Mac, управляющего Synology.
Образы скачивает Docker на NAS. Проверки с Mac разработчика не доказывают
доступность реестров, совместимость процессора или права каталогов на NAS.
Пользователь сообщил, что сейчас доступа к NAS нет.

На последнем скриншоте проект дошёл до скачивания образов и остановился на
`pull access denied for minio/minio`. Это уже не прежняя ошибка формата
`env_file`. Запуск PostgreSQL/MinIO и отсутствие прежних данных не подтверждены
текущим осмотром NAS. Не удалять каталоги и не менять пароли по этому скриншоту.

На Mac разработчика сейчас Docker daemon не запущен. Проверка конфигураций
и удалённых manifests выполнена, но нового запуска контейнеров в этом аудите
не было. Успешные контейнерные тесты из предыдущей сессии — отдельные результаты.

## Подтверждённые проблемы комплекта

1. **Старый адрес образа.** В NAS и корневом compose закреплён
   `minio/minio:RELEASE.2024-05-10T01-41-38Z`. Анонимный запрос manifest через
   временный пустой Docker config сейчас возвращает `denied` / `unauthorized`.
   Manifest той же версии на `quay.io/minio/minio` доступен, содержит amd64 и
   arm64. Это проверка manifest, не всех слоёв образа и не загрузки с NAS.
2. **Скрипт вновь выдаст старую конфигурацию.** `prepare-mac.command` закреплён
   на `e0d59bd...`, а повторный запуск сохраняет прежний ZIP. Поэтому смена строки
   только на NAS не исправляет скрипт и уже выданные архивы. Старый ZIP нельзя
   снова распаковывать поверх исправленного compose. Будущее обновление должно
   менять только конфигурацию, сохраняя `.env` и реальные пути данных; для новых
   комплектов revision и SHA обновляются вместе.
3. **Устаревшая версия MinIO.** Выпуск мая 2024 предшествует исправлениям
   безопасности, включая CVE-2025-31489 (исправление апреля 2025). Проект MinIO
   Community архивирован владельцем 25 апреля 2026. Смена Docker Hub на Quay
   решает адрес скачивания, но не актуальность/сопровождение. До постоянного
   использования нужен отдельный выбор проверенной исправленной сборки с
   понятным источником и обновлениями. Нельзя заменять образ на случайный fork
   или `latest` без проверки API, архитектуры и хранения данных.
4. **Инструкция рабочего ПК не готова для копирования на Mac.** В
   `.env.operator.example` стоит `RAW_LOGS_HOST_PATH=C:/PrinterLogs`, а команды
   README приведены в PowerShell. Это относится к вычислительному рабочему ПК,
   не к NAS и не обязательно к Mac, который используется только для управления
   Synology. Для Mac-оператора нужен локальный существующий путь и команды bash.
5. **Не подтверждена доставка образов приложения на чистый рабочий ПК.** Запрос
   manifest `ghcr.io/artemivanchenko/printers-companion:api` вернул `denied`;
   анонимный запрос `:base` также вернул `denied`. Это не доказывает удаление:
   возможны отсутствие публикации/приватность/ограничения доступа. CI проверяет
   тесты и миграции, но не публикует эти образы. Dockerfile.api наследует `:base`.
   Нужно либо проверить доступные версионированные образы обеих архитектур,
   либо явно подготовить локальную сборку base перед остальными сервисами.

## Что прошло сейчас

- NAS compose прошёл `docker compose config --quiet` с фиктивными секретами.
- Объединённая конфигурация operator + migration прошла ту же проверку с
  фиктивными значениями и без чтения корневого `.env`. Версия Compose здесь 5.1.2,
  это не версия Container Manager удалённого NAS.
- Manifest `postgres:16-alpine` доступен; содержит amd64 и arm64.
- NAS compose содержит только PostgreSQL и MinIO. API/Redis/workers на NAS
  запускать не нужно.
- `9001` сознательно не опубликован. Недоступность веб-консоли по этому порту
  не означает отказ S3; приложение использует `9000`.

## Что проверить на NAS одним обследованием

| Проверка | Возможный следующий отказ | Как закрыть до переноса рабочих данных |
|---|---|---|
| Модель, процессор, DSM, Container Manager | `no matching manifest`, `exec format error`, `CPU does not support x86-64-v2` | Сверить CPU и image. Закреплённый MinIO использует UBI9; amd64 сам по себе не доказывает поддержку x86-64-v2. Данные о модели пока отсутствуют. |
| DNS, HTTPS, часы, прокси на NAS | timeout, ошибка сертификата, denied/ограничение реестра | С самого NAS скачать оба согласованных образа до запуска. Наличие Tailscale не даёт NAS автоматически доступ в интернет через Mac. |
| Папка проекта и содержимое хранилищ | новый пустой экземпляр вместо прежнего; несовместимая версия БД | Сверить фактические пути `postgres`/`minio`, наличие `PG_VERSION`, исходную major-версию. Ничего не очищать. |
| `.env` именно в папке проекта | missing variable, неверный пароль | Проверить имена обязательных переменных и наличие значений без вывода секретов. Не использовать `.env.txt` или закомментированные строки. |
| Права на каталоги и ACL | `permission denied`, неудачный initdb | Проверить доступ контейнерного пользователя к точным каталогам. Не выдавать всем `777` и не менять рекурсивно права всего тома. |
| Свободное место, состояние тома, память | read-only filesystem, no space, OOMKilled | Проверить Storage Manager и Resource Monitor. Память/свободное место неизвестны; «слабый NAS» недостаточно для расчёта лимитов. |
| Занятость 5433 и 9000 | `address already in use` | Проверить существующие контейнеры/службы и привязки портов. Не останавливать неизвестные проекты. |
| Tailscale и правила доступа | NAS виден, приложение не подключается | Проверить TCP 5433 и HTTP readiness 9000 с того Mac, который будет клиентом; отдельно из контейнера приложения. DSM в браузере не доказывает доступность SQL/S3. |
| Firewall | лишний доступ извне или блокировка операторов | Проверить порядок и итоговую политику правил. Одно разрешающее правило не запрещает остальные источники. Не отключать firewall; не открывать порты на роутере. |
| Реальная авторизация | healthy, но приложение получает authentication failed | После готовности проверить SQL по TCP с настоящим паролем и отдельный S3 write/read с SHA-256. Healthcheck не заменяет проверку учётной записи. |
| Инициализированная БД | новый `.env`, но старый пароль пользователя | Переменные официального PostgreSQL применяются при первоначальной инициализации пустого каталога. Сохранять прежний `.env`; при необходимости менять пароль штатно, не удаляя БД. |
| Обновление схемы и идентификатор ПК | API отказался стартовать или конфликт владельца | Однократная миграция с рабочего ПК, затем API/worker; уникальный COMPUTE_NODE_ID и постоянная локальная `.operator-state`. |

## Порядок дальнейших действий

1. Подготовить согласованный комплект: поддерживаемая сборка хранилища,
   совместимость CPU, фиксированный образ/хеш и инструкция Mac. Проверить
   сохранение секретов при обновлении уже подготовленного комплекта.
2. Когда появится доступ, снять за один проход сведения о NAS, каталогах,
   свободном месте, памяти, портах и текущих контейнерах. Отчёт не должен
   содержать `.env`, токены, пароли или полный `docker inspect` с environment.
3. На NAS отдельно проверить загрузку обоих образов. Затем проверить compose
   и запуск без пересоздания каталогов данных.
4. Подтвердить готовность, авторизацию SQL и запись/чтение небольшого тестового
   объекта с рабочего ПК. Тест использует собственный ключ; не трогает чужие
   файлы. После этого провести миграцию приложения один раз с рабочего ПК.
5. Проверить одну тестовую карточку, модель и лог; результат должен считаться
   на исходном ПК и быть виден другим. Проверку сохранности после перезапуска
   проводить только в согласованное окно, не останавливая NAS самовольно.

До этих проверок установка не считается принятой. GitHub CI, локальные тесты,
успешный manifest и зелёный индикатор контейнера по отдельности этого не доказывают.
Этот аудит не изменяет конфигурации, данные, firewall или пароли и не является
сообщением о применённом исправлении.
