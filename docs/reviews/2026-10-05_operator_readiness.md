# Подготовка операторского выпуска 1.8.0

Дата: 05.10.2026. Проверенный функциональный commit:
`a306752ab65f0bd027a61220434e15e4fe3ab76f`.

## Исправлено при проверке

1. Pipeline выпуска теперь передаёт проверенные immutable digests вычислительных
   образов в native-пакеты того же SHA. Release с установщиками и SHA256SUMS
   создаётся только после контейнерной и трёх платформенных проверок.
2. Согласованы VERSION, desktop package и lock metadata: 1.8.0.
3. Windows file lock больше не читает чужой заблокированный байт до попытки
   захвата: второе обновление получает штатный отказ, а не PermissionError.
4. PowerShell smoke использует двойные кавычки вокруг пути EXE с типографским
   апострофом. Ранее команда не разбиралась самой PowerShell.
5. Только headless smoke использует software renderer на Intel runner без GPU;
   нормальный запуск оператора сохраняет аппаратное ускорение.
6. Ручной запрос после загрузки STL присоединяется к активному заданию тех же
   входов, не конкурирует с автоматическим. Parent row lock обновляет revision;
   dedup включает owner, геометрию и снимок настроек/пресета. Lease/generation
   не меняются, публикация по-прежнему проверяет входы и fencing. После завершения
   ручной пересчёт создаёт новый запрос. Изменившиеся параметры не объединяются.
7. Тестовый harness изолирует write-admission state; проверки пустых/невалидных
   calibration inputs перенесены на существующий контракт `timings`, без
   дополнительного production compatibility-пути.
8. Инструкция операторам — `docs/OPERATOR_GUIDE.md`; исследовательские JSON из
   принтерных файлов исключены из публичного Git/Docker context и сохранены локально.

## Публикация и оставшиеся ограничения

Изменения отправлены в `codex/operator-ready-1.8.0`,
[PR №26](https://github.com/ArtemIvanchenko/Printers-companion/pull/26).
Прямая запись большого комплекта в default main была отклонена защитной
проверкой; у пользователя запрошено отдельное подтверждение слияния/выпуска.
На момент этой записи main/tag/Release v1.8.0 не менялись.

До операторского допуска ещё нужны: подтверждённый merge и выполненный release
pipeline с digests; согласованный переход старой pre-protocol 1.7.0 установки;
проверка целевого NAS и конкретных рабочих ПК. NAS автоматически не мигрирует.
Для настоящего автообновления пакета — подпись/нотаризация и acceptance A→B.
Unsigned channel остаётся выключенным. Нельзя объявлять релиз/автообновление
готовым на основании одного зелёного PR или выдать исследовательские результаты
за доказанную точность времени всей печати.
