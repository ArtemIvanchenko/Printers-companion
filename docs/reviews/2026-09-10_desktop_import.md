## Сопоставление и ограничения

Проверка выполнена по SHA исходников и происхождению из инвентаризации; смешанных

97 карточек, из них прежние 8 со связанными логами. Повторная проверка кандидатов — 0.

Резервная копия перед очисткой:

### Ограничения исходного сопоставления

- Восемь прежних связей переиспользованы только при совпадении SHA Magics и
  имеющейся сессии с подборкой «Подтверждённые печати». Это сохранение архивных
  связей, не независимое подтверждение качества изделия или всех параметров режима.
- Остальные 19 наборов не получили новых связей с моделями по одному совпадению
  даты. Они доступны как сессии без карточки. Отдельные суточные наборы не обязательно
  означают отдельные реальные печати.
- В июльских наборах имеются sensors/stateFlow, но отсутствуют основные журналы
  и `*_time.log`. Время прожига, слои и полное нормальное время ими не подтверждаются.
  Большие stateFlow сохранены как исходники, не декодированы в подтверждённую схему.
- Три укороченные версии логов побайтово совпадают с началом более полных версий.
  Они отдельно сохранены в MinIO, но повторно не анализировались.
- RAR «Тестовое задание» содержит STL с SHA
  `f3041d42c726cea489735448c8956b87c743f9e39e4e46a0750372a02959418c`:
  извлечение в поток через bsdtar подтвердило совпадение с уже импортированным STL.
- `RS-300 60 mkm test1.magics` и `Test.magics` сохранены, но печатные тела
  поддерживаемого формата из них не декодированы. Ошибка указана в отчёте карточки.
- Нативные поддержки Magics не восстановлены; начало Z, режим и материал неизвестных
  файлов не угадывались. Новые прогнозы по ним не создавались.
- Прежние прогнозы восьми переимпортированных карточек сохранены в metadata
  `desktop_previous_prediction` и отдельными документами. Они убраны из активного
  сравнения с новым фактом до повторного расчёта. Архивные пояснения о толщинах
  слоя не являются независимым измерением и не должны автоматически становиться
  обучающей разметкой.
- У карточки 8–9 июня осталось прежнее имя про SIU, тогда как исходная подборка
  названа «Образцы ГОСТ»; это расхождение источников, не основание молча менять пару.

## Где смотреть

http://127.0.0.1:8000/ → «С анализом» → карточка → «Что печатали»,
«Как прошло», «Процесс», «Файлы». Для всех карточек и поиска — «Список».
Пример: «RS-320: Хвостовики + Корпусы, партия 2 (27.05.2026)».

Фильтр «С анализом» выбирает связанные карточки до пагинации. Превью предпочитает
STL детали, а не первый файл поддержек. Источники/ограничения видны непосредственно
в карточке. Полная компоновка не подменяется первым STL: подпись показывает именно
отображаемый файл; остальные модели доступны во вкладке «Файлы».

## Повторный локальный запуск

Открыть OrbStack. Из корня проекта:

```sh
.venv/bin/python scripts/maintenance/desktop_runtime.py start
```

Команда поднимает существующие контейнеры хранения, локальный proxy, API и два
отдельных локальных worker: импорт логов и расчёт времени.
API слушает только 127.0.0.1:8000; proxy PostgreSQL — 127.0.0.1:55432.
Занятые порты не освобождаются принудительно. Логи запущенных процессов —
`.operator-state/desktop-import/{proxy,serve}.log`. Секреты читаются в памяти
из текущих локальных контейнеров, не копируются в этот документ/скрипт.

Оба worker входят в `start`; запуск одного экземпляра импорта отдельно для диагностики:

```sh
.venv/bin/python scripts/maintenance/desktop_runtime.py worker
```

Повторяемые операции импорта:

```sh
.venv/bin/python scripts/maintenance/desktop_runtime.py run -m scripts.maintenance.desktop_inventory
.venv/bin/python scripts/maintenance/desktop_runtime.py run -m scripts.maintenance.populate_desktop logs
.venv/bin/python scripts/maintenance/desktop_runtime.py run -m scripts.maintenance.populate_desktop models
# После завершения всех заданий:
.venv/bin/python scripts/maintenance/desktop_runtime.py run -m scripts.maintenance.finalize_desktop_import
```

Для будущего NAS этот локальный запуск не использовать: он предназначен для
существующего OrbStack на данном Mac. Внешний LLM отключён; данные ни в OpenRouter,
ни в другие внешние ML-сервисы в ходе этого импорта не отправлялись.

Дополнение: переносимый каталог, исправления ZIP-импорта, сетка по 10 карточек и
восстановленный запуск worker расчёта описаны в `docs/IMPORT_BUNDLES.md`.
