# Nemotron Ultra — архитектурное ревью

Сессия: `ses_f9b049633ffe5fa3114YnyAeOo`

> Это внешний read-only аудит. Номера строк и утверждения необходимо сверять с
> текущим рабочим деревом перед реализацией.

## 1. Перегруженный `api/routes/prints.py`

Маршрут смешивает HTTP, MinIO, загрузки STL, расчёт прогноза, калибровку,
очереди, SSE и проверки геометрии. Предложено вынести:

- `domain/services/print_card.py` — CRUD, вложения, связь с сессией;
- `domain/services/print_estimation.py` — подготовка, расчёт и публикация;
- `domain/services/print_calibration.py` — калибровка и точность;
- `api/realtime/print_events.py` — события интерфейса.

## 2. Слишком широкий `storage/repositories/runtime.py`

Один repository обслуживает import jobs, сессии, отчёты, журнал оператора,
quality outcomes, verdicts, insights, source files и canonical events. Ответ
предлагает постепенно выделить отдельные repository по этим агрегатам.

## 3. Связь аналитики и persistence

API и import worker напрямую вызывают модули калибровки с DB session. Предложен
`calibration_orchestrator` с фазами: коротко подготовить входы, считать без
соединения с NAS, коротко применить результат. Долгую калибровку выполнять job.

## 4. Пробелы provenance

Прогноз и реестр моделей уже сохраняют значительную часть provenance. Внешний
аудит предлагает отдельно проверить наличие `parser_versions` в сессиях и
версий defect-risk модели в каждом сохранённом прогнозе.

## 5. Безопасность миграций

Линейная цепочка 0001–0021 и `assert_schema_at_head()` отмечены положительно.
Ответ ошибочно предположил отсутствие `scripts/check_migration_drift.py`; файл
нужно проверять локально, а не создавать по этому утверждению вслепую. Полезная
часть рекомендации — закрепить проверку единственной Alembic head в CI.

## 6. Compute affinity и lease

Ownership, generation fencing и heartbeat worker отмечены положительно.
Предложено проверить, не остаётся ли API-путь расчёта через локальный
`ProcessPoolExecutor` без собственного lease; тяжёлые оценки лучше всегда вести
через выделенный `print_estimate` job.

## 7. Монолитный `web_templates/dashboard.html`

Предложено поэтапно вынести ES-модули:

- графики;
- STL viewer;
- realtime/SSE;
- отдельные вкладки.

HTML должен остаться тонкой оболочкой.

## 8. Дублирование разрешения параметров машины

Проверить дублирование между `params_for_record` и `machine_settings`; оставить
один сервис разрешения параметров конкретной карточки и одну валидацию входов.

## 9. Тихая потеря интервала неопределённости

Широкий `except` при обогащении прогноза может оставить оператору только точку
без объяснения. Предложено хранить явные `prediction_interval: null` и
`interval_unavailable_reason`.

## 10. Версия geometry cache

Ручной `_GEOMETRY_CACHE_VERSION` можно забыть повысить при изменении схемы
слойной геометрии. Предложено экспортировать стабильную
`LAYER_SERIES_SCHEMA_VERSION` из layer engine и включать её в ключ.

2. Вынести orchestration калибровки и тяжёлые расчёты из API-транзакций.
3. Довести provenance и CI-проверку миграций.
4. Затем разделить dashboard и унифицировать параметры машины.
