# Сквозной рефакторинг архитектуры — 23 сентября 2026

## Область и граница результата

Изменены исходники и тесты локального checkout. Работающий NAS, операторские
базы, исходные модели/логи, секреты и существующие контейнеры не изменялись.
Коммит, публикация на GitHub и установка на втором ПК в этот этап не входят.
Существовавшие незакоммиченные изменения сохранены.

Это переход к единым сценариям и опубликованным результатам, а не обещание
«в проекте больше нет ошибок» и не механическое сокращение числа файлов.

## Что изменено

### 1. Один измеренный анализ вместо независимых сводок

`session_analysis.py` один раз готовит интерпретацию событий, классификацию,
признаки, слои и сегменты. `session_overview.py` и JSON-report используют этот
результат. `analysis_snapshot` schema v1 содержит общие компактные факты и
provenance. Публикация и чтение сверяют снимок, отдельно — timing publication.
Противоречие отклоняется; нельзя совместить новый отчёт со старой карточкой.

Дедупликация не меняет исходные parser DTO и не склеивает различающиеся попытки
слоя только по близкому времени события. Временные измерения по-прежнему проходят
собственный допуск OLD/NEW и повторов, а не общий семантический dedup.

`machine_min` сохранён для совместимости как подытог burn+pour. Его разница с
wall-clock больше не называется простоем. Отдельно хранятся подтверждённые
паузы, нераспределённый остаток и нормальный цикл измеренных допустимых слоёв.
Отсутствие измерений не доказывает нулевую длительность печати.

Последняя проверка обнаружила старый обход этих правил в сводке каталога.
`print_cards/comparison.py` теперь готовит один summary v2 для списка и карточки:
старый прогноз сравнивается только с подытогом burn+pour, новый cycle-прогноз —
только с отдельно опубликованным normal accounting того же timing generation.
Проверяется полное покрытие 1..N, без старого 95% допуска и raw fallback.
Нет сопоставимого факта — нет процента ошибки; wall-clock и неполная сумма
сохранены отдельно в диагностике. UI использует этот контракт, не считает
собственную другую «ошибку». Текущие параметры прогноза не создают его же факт.

Это проверка контракта/поколения, не автоматическое доказательство независимости
обучения возможного normalizer. Перед его подключением нужен отдельный provenance
допуск; математические ограничения описаны в
[стратегии точности](2026-09-23_time_prediction_strategy.md).

### 2. Измерения не зависят от разрешения графика

Все доступные суточные sensor-файлы читаются до прореживания. Health, полная
статистика и soft sensors используют полный доступный локальный поток, график —
отдельную ограниченную проекцию. Одинаковые clock-only данные разных дат не
склеиваются по одному SHA. Пустое окно печати не подменяется точками вне окна.

Неполное покрытие, отсутствующие источники, перекрытия и bounded parser fallback
отмечаются явно. Полнота доступного потока не доказывает полноту копии со станка.
Большие массивы не добавлены в PostgreSQL. Полезные burn/table-temp источники
больше не отбрасываются глобально; исключения/лимиты находятся в профиле.

Граница: проверка производительности и пиков памяти на многосуточных реальных
печатях ещё нужна. Вспомогательные bounded parser tables не стали полным архивом.
Полноценный универсальный multi-machine context пока не реализован.

### 3. HTTP не выполняет повторный импорт на чтении

Новые session read models выполняют SQL, копируют данные и освобождают соединение
до обращения к MinIO. GET читает опубликованный отчёт, без разбора raw, записей
и process-local report cache. Недоступность MinIO допускает ограниченный SQL
fallback; несовпадающий объект отчёта — конфликт, не новый источник истины.

Ingest/analyze/reanalyze получили явный контракт v2/202 и job ID. Пересчёт идёт
через исходный owner-local ImportJob с fencing. Без доказанной связи legacy-
сессии с исходным job необходимо заново загрузить логи, путь не угадывается.
`/reports/generate` только форматирует уже опубликованный JSON.

### 4. Восстановление прерванной браузерной загрузки

Квитанция v2 сохраняет исходный job и политику подтверждения. Worker периодически
проверяет собственные прямые квитанции в incoming. Сначала проверяется immutable
job ID в БД: успешный, но не подтверждённый клиенту commit не порождает дубль.
Если job отсутствует, проверяются SHA/размер/полный состав пакета вне SQL, затем
работает единый publisher HTTP/recovery под общей блокировкой.

Уже захваченный lease/generation не сбрасывается. Старая v1 без сохранённой
политики не считается автоматически подтверждённой. При NAS outage действует
backoff; неоднозначный пакет остаётся needs_attention. Исходники не удаляются.

### 5. ML и экспериментальные методы отделены от обязательной обработки

Версия аналитики повышена до 0.5.0. Снимки со старой семантикой не смешиваются
с новыми признаками в обучении. Старый active-артефакт остаётся в реестре, но
не применяется к новой аналитике. Новая модель также не получает старые
display-признаки: используется эвристика с предупреждением о повторном анализе.
Старые карточки/разметка не удалены и автоматически не переписаны.

Дополнительные эксперименты запускаются вручную через отдельное owner-local
задание `shadow_analysis`, в spawn-процессе с timeout. Результат сохраняется в
задании после проверки входов и lease, не в карточке/измеренном отчёте. Текущий
эксперимент работает над сохранённым preview и временами слоёв, явно сообщает
это ограничение; process mining без полного потока событий недоступен.

Заглушки daily review теперь имеют честный not_implemented, исторический
prototype — experimental_manual. Межэтапная проверка бюджета не выдаётся за
принудительный timeout отдельных алгоритмов.

### 6. Интерфейс и нагрузка на NAS

HTML-шаблон уменьшен приблизительно с 5603 до 1103 строк. CSS и JS вынесены по
сценариям в `web_assets/dashboard/`, внешний вид и действия сохранены.
Chart.js, Three.js и шрифты закреплены локально, с лицензиями и SHA manifest.
Отсутствие визуальных библиотек не ломает базовое создание карточки/навигацию.

В формах карточки и списках вложений убраны опасные HTML-вставки имени файла,
заметок и значений полей: экранирование данных, URL-encoding идентификаторов,
передача имён обработчикам через замыкания вместо вставки в inline JavaScript.
Это целевая защита затронутых представлений, не полный security-аудит всего UI.

GET `/` — SQL-free оболочка. Исторические страницы ограничены 100 строками и
загружаются по запросу. Телеметрия не скачивает полные массивы всех сессий ради
сводного списка; полные данные запрашиваются для выбранной сессии.

Измеренные запросы: HTML — 0, страница sessions/timeline/consumption — 2,
quality с агрегатами — 4, компактная страница telemetry — 2. Это не утверждение,
что все асинхронные виджеты главной обходятся без SQL. Quality aggregates описывают
записи контроля, а не обучающую выборку подтверждённых исходов.

### 7. Сборка, зависимости и готовность

Единый build manifest содержит версию, SHA, source_state, дату и build ID.
Release вычисляет SHA после version commit. Запускатели готовят identity до
сборки и сверяют запущенный API; readiness проверяет SQL, Alembic head, Redis,
авторизованное чтение MinIO и бакеты. Запись объектов и наличие живых worker
этим не доказаны: capabilities остаются unknown, пока нет отдельной проверки.

Декларации dependencies/tier membership/существующие Docker pins находятся в
pyproject. Requirements генерируются stdlib-скриптом, CI проверяет --check.
Версии библиотек не обновлялись; native-диапазоны не заменены Docker pins.
Полного transitive/cross-platform lock ещё нет. CI дополнен сборкой настоящего
API-контейнера и проверкой identity/liveness/честной деградированной readiness;
локально эта Docker-проверка не запускалась.

Корневой compose использует Quay для той же версии MinIO. Закреплённый initial
NAS bundle не переиздан: его registry/pin требует отдельной проверенной публикации
compose, затем связанного revision+SHA обновления installer. Нельзя подставлять
выдуманный SHA или заменять пароли/volumes уже работающей БД.

## Проверки

- Полный изолированный pytest: **1125 collected / 1125 passed**, 13 предупреждений
  существующих зависимостей и намеренных preflight-проверок.
- Чистая SQLite: upgrade всей цепочки до единственного `0021_layer_cycle_models`;
  Alembic check — без новых операций; migration drift — OK.
- Ruff и `git diff --check` — без ошибок; generated requirements --check — OK.
- Chromium + отдельный тестовый API/SQLite/outbox: карточки 10 → 20, навигация,
  lazy history, 0 pageerror, 0 внешних браузерных запросов. Повтор с недоступными
  Chart/Three: создание карточки работает, показаны ограничения графиков.
  Тестовый API остановлен. Настоящая 3D-модель в этом smoke не проверялась.
- Регрессии: snapshot mismatch rollback, неизменность фактов при 150 → 7 точках
  графика, все суточные источники, несовместимость старых ML-признаков, timeout
  shadow-child, owner/fence и гонка HTTP/recovery без сброса lease.

PostgreSQL-конкурентность, реальный object round-trip, полный Docker stack и
установка на втором Mac/Windows/NAS не проверены этим локальным прогоном.
Это отдельный release gate, не скрытый «успех» по зелёному unit-тесту.
