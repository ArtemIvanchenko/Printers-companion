## Правильная схема расчёта точного времени

Для каждой пластины нужно сохранять экспорт проекта или read-only выгрузку
таблиц стратегии. Без неё параметры с фотографий остаются ручным вводом.

Расчёт должен идти по слоям:

1. `N = ceil((max_z - build_origin_z) / layer_thickness)`; начало координат
   сохраняется явно.
2. Для каждого слоя строятся реальные контуры, hatch, up/down-skin, поддержки,
   переходы и распределение по лазерам.
3. Время прожига — сумма длин траекторий/скоростей, задержек и ускорений. Для
   нескольких лазеров нужен makespan наиболее долгого канала, а не слепое
   деление общего пути на число лазеров.
4. Полный нормальный цикл слоя:
   `max(scan + recoat + base_overhead, minimum_layer_cycle)`.
5. Общее время — сумма нормальных циклов всех слоёв. Паузы, аварийные простои и
   повторные попытки показываются отдельно и в прогноз не добавляются.
6. `burn_ms`, `pour_ms`, `make_layer_ms` калибруют отдельные компоненты.
   Потерянные/повторные строки не выдаются за измерения.
7. Проверка точности выполняется блоками одинаковой геометрии во временном
   holdout, чтобы повтор одной пластины не попал одновременно в обучение и тест.

Ближайший наиболее ценный источник данных — безопасный экспорт таблиц
`Projects`, `Models`, `EquidistantsStructure`, `HatchsStructure` и
`SupportsStructure` с машины. Приложение не должно подключаться к производственной
БД с привилегированной учётной записью.

## Безопасность

В `M350/PMDeploy/settings.db` обнаружены реквизиты привилегированного подключения
к SQL Server в открытом виде. Значение пароля в отчёт не скопировано и соединение
не выполнялось. Пароль следует сменить, для выгрузки создать отдельного
пользователя только на чтение, а секрет убрать из поставки/флешки.

Файлы `Mapus1.MCD`–`Mapus5.MCD` являются документами Mathcad, а не заданиями
принтера; использовать их как источник параметров слайсера нельзя.
