## Разделитель таблицы не выбирается повторно по значениям каждой строки

Воспроизведение: заголовок `Time SO1 SO2`, строка `12:00:00 0,1 0,2`.
Существующий `split_row` видел две запятые и переключался с whitespace на CSV:
в таблице SO1 становился строкой `1 0`, SO2 — числом 2; в полном потоке —
SO1=null, SO2=2.0 вместо 0.1/0.2. Число полей случайно совпадало, поэтому
malformed_rows оставался 0. Та же ошибка портила дробные StateFlow-значения.
Это ошибка поддерживаемого формата, не основание переименовать датчики/единицы.

Прежний выбор разделителя вынесен в `table_delimiter` без изменения его
приоритетов. `parse_table_stream`, `sensor_samples` и StateFlow используют его
один раз для первой непустой строки и передают выбранный разделитель в тот же
`split_row`. Фильтрация, reservoir sample, часы и сопоставление колонок прежние.
Повреждённая строка с другим разделителем получает существующую width-диагностику,
а не случайную интерпретацию другого формата. Quote-правила CSV сохранены;
`|` внутри неизвестной ячейки CSV/semicolon/tab не меняет формат строки.
Без заголовка разделитель по-прежнему определяется первой строкой; новой
эвристики восстановления неизвестного формата не добавлено.

Парсеры Sensors/Burn/TableTemp: 0.2.2; StateFlow: 0.2.3. Пользователь явно
разрешил дальнейшую передачу результатов основному чату и согласование общих
версий без повторных вопросов. Сообщены требование согласованной аналитической
версии и две жёсткие проверки прежней StateFlow версии в общем тесте (142–143);
общие constants/чужой тест данный чат не редактирует. Основной чат выполнил
согласованную интеграцию: ANALYSIS_VERSION 0.5.8, LOG_INSIGHTS_VERSION 1.0.9,
две проверки StateFlow теперь ожидают 0.2.3. Это независимо подтверждено
чтением соответствующих файлов после изменения.

Первоначальные 11 сценариев: 7 fail / 4 control pass до исправления.
После: 53 целевых parser/stream проверок прошли; расширенный прогон 93 pass /
1 fail — только ожидаемая 0.2.2 вместо фактической 0.2.3 в существующем
