# Защиты применимости прогноза и честности метрик

Дата: 26 сентября 2026. Первый реализованный блок после
[аудита стратегии](2026-09-23_time_prediction_strategy.md).
Это проверка исходного кода и синтетических регрессионных примеров, а не
подтверждение процента ошибки на новых реальных печатях. Рабочая БД, исходные
логи, NAS и ранее сохранённые прогнозы не изменялись.

## 1. Что изменено

### Область применимости модели прожига

Новый `analytics/prediction/scan_scope.py` формирует `configured-scan-v1`:
физическая машина, материал, толщина, скорости штриховки/контуров/поддержек/
переходов, задержка перехода, шаг штриховки, число лазеров и доступные ID
пресета/стратегии, версии слайсера/прошивки. Учитывается фактический выбор
настроенной скорости для материала; цены и результаты калибровки в этот hash
не входят. Версия включает политику дефолтов и геометрического scan-алгоритма.

Состав и hash сохраняются в новом снимке расчёта и fitted NNLS-артефакте.
Обучающие пулы разделены по scope. Выбор модели проверяет полный состав,
а не только имя ключа. Неизвестная машина, изменение любого учитываемого
параметра, повреждённый артефакт или отсутствующий старый scope исключают
NNLS из нового расчёта. Используется физический расчёт с предупреждением.

Старым снимкам не дописывается сегодняшний пресет. История не меняется задним
числом. Новый снимок после пересчёта также **не доказывает**, что прежняя печать
исполняла текущие настройки: нужен независимый экспорт или подтверждение.

Связанная сессия определяет машину измерения. Конфликт её printer_id с
прогнозом исключает scan/cycle-калибровку, а не переносит тайминги под другой
ключ. Отсутствие STL не блокирует независимые измерения цикла, если физическая
машина известна и отсутствует противоречие.

### Одна проверка полноты измерений

`timing_validation.has_complete_layer_coverage` используется в карточке и
старой accuracy/ratio-калибровке. Для целой печати нужны ровно слои 1..N:
без пропуска, лишнего слоя и неоднозначного/неизвестного N.

Убраны правила «95% достаточно» и «без N достаточно 100 строк». Пример:
990 из 1000 слоёв больше не создают полный факт, ошибку времени или ratio для
обучения. При этом достоверные отдельные слои остаются полезны для scan fit.
Scope старой accuracy остаётся burn+pour, не normal cycle; покрытие не
доказывает отсутствие остановки внутри принятых фаз.

### Идентифицируемость base/floor

Модель цикла имеет контракт `max_base_floor_v2`:

```text
cycle = max(burn + pour + base, floor)
```

Если все наблюдения ограничены floor, base остаётся null и кандидат не
применяется. Алгоритм не превращает неизвестную добавку в найденное число.
Для определения обоих параметров нужны наблюдения обеих веток в нескольких
независимых компоновках. Одни свободные слои допускают аддитивную модель лишь
при достаточном изменении входов и без существенного свидетельства в пользу
излома; сохраняется нижняя граница наблюдённой суммы burn+pour.

Аддитивная модель без определённого floor не применяется к прогнозу с более
короткими слоями. V1 и старый additive-артефакт не используются как доказанно
идентифицированный V2. Требуется новая калибровка, не переименование версии.

Пример регрессии: при burn+pour около 9–10 с и одинаковом цикле 18 с нельзя
объявлять base около 8–9 с и добавлять его к будущему длинному слою. Новый
отрицательный тест оставляет base неизвестным.

### Проверка каждой печати без погашения ошибок

Повторы одной геометрии, как и прежде, удерживаются вместе. Теперь внутри
holdout-блока считается ошибка каждой физической печати отдельно.
Контрпример двух повторов даёт +25% и −16,67%, а не нулевую ошибку после
сложения их длительностей. Единица метрики сохранена явно:
`cv_error_unit=print_with_geometry_held_out`.

Это grouped CV по доступным измеренным слоям, ещё не проверка полного времени
на будущих печатях. Временное разделение и end-to-end normal-cycle gate нужны
отдельно.

## 2. Совместимость и эксплуатация

- `ANALYSIS_VERSION` повышена с 0.5.0 до 0.5.1. Старые результаты не получают
  новую версию простым редактированием JSON; для новой аналитики нужен пересчёт.
- Схема БД и HTTP-контракт фоновой калибровки v2 не менялись; новой миграции нет.
- Текущие модели читаются только при выполнении новых допусков. Существующий
  механизм публикации автокалибровки по-прежнему удаляет неподдержанные ключи
  из рабочего реестра при следующем запуске; данная работа его не запускала.
- Вычисления остаются на ПК оператора, чтение/публикация короткие, fencing и
  контроль свежести входов сохраняются. NAS не получает новые вычисления.
- Некоторые старые карточки теперь покажут неизвестный факт или физический
  прогноз без калибровки. Это ожидаемый отказ от недоказанного результата,
  а не потеря исходных логов.

## 3. Проверка

Регрессионные примеры находятся в `tests/analytics/test_time_model_guards.py`;
сквозные случаи — в тестах scan/background calibration, plate estimator,
prediction accuracy/contract и карточек. Полный pytest запускается в
изолированной временной SQLite с отключённым чтением рабочего `.env` и
отдельным NAS-outbox.

Финальный результат:

- `pytest tests -q -o addopts= --tb=short` в изолированном harness:
  **1164 passed**, 48,04 с, 13 предупреждений; ошибок нет.
- `ruff check .`: все проверки пройдены.
- `python scripts/export_requirements.py --check`: зависимости соответствуют
  `pyproject.toml`.
- `git diff --check`: ошибок whitespace нет.

Предупреждения относятся к deprecation сторонних библиотек/Alembic и
намеренным тестам дефолтных токенов. Они не свидетельствуют о прочтении или
изменении рабочего `.env`. Проверка удалённого развёртывания не проводилась.

## 4. Что не закрыто этим блоком

1. Настроенный scope не равен подтверждённой стратегии станка. Нужны manifest,
   поддерживающая геометрия, положения/ориентации и реальный рецепт экспозиций.
2. Cycle пока группируется по машине/материалу/толщине/лазерам; recoat и ratio
   используют ещё более широкие ключи. Полный phase-recipe допуск не сделан.
3. Cycle gate учитывает объём/идентифицируемость, но ещё не ошибку удержанной
   печати относительно baseline. Старый residual guard 60 с предварителен:
   превышение не устанавливает причину и может исключить настоящий длинный floor.
4. Нужны траектории по областям и лазерам, их реальный порядок/параллельность,
   полный послойный reference и измеренная ошибка геометрического приближения.
5. Нужны замороженные before-print прогнозы, независимый нормальный факт,
   grouped temporal validation и затем обоснованные интервалы/ML остатка.
6. Работоспособность изменённой сборки на удалённом Mac/NAS, обновление GitHub
   и её точность на новых печатях этим локальным прогоном не подтверждены.
