# Послойная диагностика логов

Версия аналитики 0.4.0. Расчёты локальны, отчёты диагностические; вероятность
дефекта по этим показателям не назначается.

## Что реализовано

1. Потоковый проход по полным сенсорным файлам, синхронные значения каналов,
   все переходы через полночь. Интеграл превышения вычисляется как площадь
   положительной части линейного участка, с точным пересечением порога и
   обрезкой по окну прожига. Пропуски длиннее 5 с не заполняются. Покрытие
   считается отдельно по каждому каналу. Общая метка прожига даёт приблизительное
   окно; без временной метки слоя расчёт не подменяется прогрессом печати.
2. После явного возобновления ищется 30-секундный непрерывный участок показаний
   в заданных пределах. Отсутствующие отсчёты разрывают его. Дополнительно
   сравниваются до пяти слоёв до/после события. Это не доказательство причинности.
3. Новый прогноз сохраняет применённые коэффициенты прожига. По геометрии слоя
   строится ожидаемое время, систематическое смещение отделяется от локальных
   выбросов медианой/MAD. Не используется для неполной геометрии, неизвестного
   начала Z, устаревшего снимка или неподтверждённой связи с логом. Участие печати
   в обучении отмечается; диагностический остаток не является оценкой точности.
4. Повторы допускаются только по подтверждённой связи, одинаковым fingerprint
   компоновки и профиля, машине, материалу, толщине, шагу штриховки, лазерам и Z.
   Сравниваются общие физические номера слоёв без растягивания пропусков.
   Среда сравнивается при одинаковых порогах и покрытии не менее 80%.
5. Участки с превышениями и необычным остатком прожига привязываются к диапазону
   Z и активным сечениям тел. Неизвестный Z остаётся неизвестным. Общие датчики
   не определяют координату X/Y и конкретную дефектную деталь.
6. Время разделено на прожиг, порошок, штатную задержку, ожидание минимального
   цикла и необъяснённый остаток. Сумма компонентов равна фактическим циклам.
   Явные паузы и повторы не прибавляются повторно. Нормальное время требует
   калибровки и исключает неоднозначные слои; без модели нет выдуманного нуля.

Исправлены также первые-повторы в обзорной аналитике/статистике фаз и повторный
учёт одинаковой копии второй попытки. График многоcуточного сенсорного файла
сохраняет действительные даты начала и конца.

## Доступ и воспроизводимость

- Импорт сохраняет компактный блок `group.log_insights` с SHA входов,
  конфигурацией в виде хеша, версиями парсеров, аналитики и ПК вычисления.
- JSON/Markdown отчёт содержит этот блок; в карточке «Процесс» появляется
  панель шести направлений с состояниями загрузки, отсутствия данных и ошибки.
- `GET /analysis/prints/{record_id}/log-insights` читает компактные входы,
  закрывает соединение с NAS, затем считает. Поиск ограничен 100 карточками и
  десятью подходящими повторами. В отчётах до 100 подробных наблюдений; счётчики
  и агрегаты относятся ко всем обработанным точкам.
- Старые сохранённые слои не считаются автоматически повторно проверенными.
  Для новой среды нужен импорт на ПК владельца, для новой геометрической
  диагностики — пересчёт прогноза. Рабочая база в этой сессии не менялась.

Настройки: `LOG_INSIGHTS_MAX_GAP_SECONDS`, `LOG_INSIGHTS_STABLE_SECONDS`,
`LOG_INSIGHTS_CLOCK_TIMEZONE` (по умолчанию Europe/Moscow).
`LOG_INSIGHTS_THRESHOLDS` — JSON-словарь по именам каналов с полями `high`,
`unit`, `confirmed`. Пустой словарь использует предварительные ограничения
профиля, не подтверждённый режим материала. Для явно заданного набора проверяются
все перечисленные каналы; отсутствие одного не даёт объявить восстановление.

Исследовательские скрипты **не являются штатным импортом**:

```bash
python -m scripts.research.audit_log_insights /каталог/логов 09.06.2026 --output audit.json
python -m scripts.research.audit_july_sensor_run /каталог/M350-Logs --output july.json
```

Они читают исходники и сохраняют отчёт по указанному пути, но не загружают
сырьё в MinIO и не создают карточки. Исходники должны оставаться в постоянном
каталоге; временная распаковка в `/tmp` не является архивом проекта.
