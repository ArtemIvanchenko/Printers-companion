# План повышения точности времени печати

Актуальная версия на 2026-09-03. Исторические цифры из старых ревью нельзя
считать текущей истиной без повторного прогона: в них смешивались режимы,
неполные компоновки и старые трактовки времени.

## Цель и граница расчёта

Прогноз отвечает на вопрос: **сколько машина будет непрерывно выполнять
нормальную печать этой компоновки**.

В него входят:

1. прожиг лазером;
2. нанесение нового слоя порошка;
3. штатные переходы контроллера между фазами;
4. заданная машиной нижняя граница длительности слоя, если она активна.

Не входят: операторские остановки, аварийные паузы, ожидание между днями и
повторный прожиг уже выполненного слоя. Они остаются диагностикой факта, но не
увеличивают нормальный прогноз.

Для физического слоя `i` целевая формула:

```text
scan_i = fitted_geometry_model(features_i, machine, material, process_mode)
cycle_i = max(scan_i + recoat_i + base_controller_overhead,
              minimum_layer_cycle)
T_normal = sum(cycle_i for every physical layer exactly once)
```

`minimum_layer_cycle` применяется послойно. Подставить его после суммирования
нельзя: две плиты с одинаковым общим прожигом, но разным распределением времени
по слоям дадут разный результат.

## Проверенный набор

`*_time.log`. Все 95 журналов подтверждённых пар имеют исходную одноимённую
копию. Подробности и хеши: `docs/reviews/2026-09-03_archive_lineage.md`.

Нормальный цикл выше равен `make_layer_ms` с удалённым длинным pause-like
остатком и без дополнительных попыток того же номера слоя. Значения служат
эталоном парсинга; точность геометрического прогноза проверяется отдельно.

Оставшиеся восемь `*_time.log` в исходной папке не содержат измерений: они
пустые либо состоят из заголовков. Остальные модели являются кандидатами,
заготовками или будущими заданиями и не объявляются напечатанными по имени или
дате.

## Что показали реальные слои

- Медиана нанесения порошка стабильна примерно на уровне 9.25 с/слой.
- Обычный остаток `make-burn-pour` близок к 0.38–0.44 с/слой.
- В режиме `steel@0.125` простой `+ median(overhead)` неверен. Робастная
  модель `max(burn+pour+base, floor)` на двух независимых компоновках дала
  `base ≈ 0.378 с`, `floor ≈ 17.96 с`; ошибка реконструкции суммы составила
  около +0.07% и +0.62%.
- В паре 19.05 слои 40–79 выполнены повторно. Они учитываются как факт
  дополнительной работы, но не должны дважды обучать нормальный профиль слоя.
- Одинаковая запись граничного слоя в двух сшитых файлах не является второй
  попыткой и не прибавляет время.

## Правильное сопоставление модели и лога

Дата используется только для поиска кандидатов. Автосвязь разрешена при
сильном независимом доказательстве и отсутствии противоречий:

- оператор загрузил логи непосредственно из карточки;
- фактический последний слой согласован с ожидаемым числом слоёв;
- подтверждён fingerprint уже известной компоновки;
- материал/машина/режим не противоречат карточке.

Если два кандидата близки по доказательствам, связь остаётся ручной. Нельзя
выбирать лог потому, что его длительность похожа на текущий прогноз: после
такого выбора проверка этой же модели становится круговой.

## Геометрия и начало построения

`max Z`, `max Z - min Z` и физическая высота построения не всегда совпадают.
Контрпример: у пары 08 детали Magics лежат в диапазоне 3.000–250.628 мм, а
1983 слоя по 0.125 мм согласуются со span 247.628 мм, не с отсчётом от нуля.
При этом Magics содержит 13 нативных поддержек, геометрия которых текущим
reader не декодируется.

Правило:

1. явный `build_origin_z_mm` карточки/проекта имеет высший приоритет;
2. origin экспортированных и подтверждённых поддержек является сильным
   геометрическим доказательством;
3. без этих данных расчёт хранит источник origin и предупреждение, а не
   молча объявляет `Z=0` истиной;
4. число ожидаемых слоёв после привязки сверяется с логом, но фактическое
   время не используется для подгонки пары;
5. известная неполная геометрия блокирует клиентский прогноз и обучение scan.

## Калибровка без утечек

Калибровка делается для точного ключа как минимум
`printer + material + layer_thickness + process strategy + laser count`.
До появления всех полей используется более узкий доступный ключ с явным
предупреждением; перенос между толщинами запрещён.

Гейты:

- реальная печать и однозначная карточка ↔ сессия;
- полный или доказуемо сшитый `time_log`;
- полная подтверждённая геометрия;
- не менее двух **разных fingerprints компоновки** для fit;
- повторные печати одного fingerprint держатся в одном CV-fold;
- один слой с конфликтующими попытками не обучает normal scan;
- коэффициенты NNLS не называются физическими скоростями;
- принятие модели зависит от group holdout, а не от in-sample R².

Основные метрики: ошибка общей длительности каждой удержанной плиты, median
absolute percentage error, worst-case error и signed bias. Послойный R² —
диагностика формы, а не доказательство точности итоговых часов.

Интервал выводится только из ошибок целых невиденных компоновок. При числе
уникальных fingerprints меньше трёх показывается точка с предупреждением, но
не выдуманный «±10%».

## Итерации реализации

- [x] Проверить происхождение файлов по SHA-256 и различать append-only версии.
- [x] Сшивать продолжения печати по непрерывности номера слоя.
- [x] Различать одинаковый граничный дубль и материально отличающуюся попытку.
- [x] Ввести консервативный evidence-score карточка ↔ сессия; дата одна не
  создаёт автоматическую связь.
- [ ] Хранить raw `make_layer_ms`, нормальный controller residual и признак
  повторной попытки раздельно.
- [ ] Калибровать `base_controller_overhead` и gated `minimum_layer_cycle` по
  робастной послойной модели; применять floor до суммирования.
- [ ] Хранить явный build origin и источник; для неизвестного origin не
  скрывать диапазон возможного числа слоёв.
- [ ] Добавить fingerprint геометрии в снапшот и grouped cross-validation.
- [ ] Исключать неполную компоновку из scan/time fit автоматически.
- [ ] Выводить интервал только после достаточного group holdout.
- [ ] Прогнать восемь подтверждённых пар через production pipeline, сохранить
  воспроизводимый отчёт `predicted vs normal actual` и исправлять худший fold.

## ML после накопления истории

Сейчас восемь печатей недостаточны для честной нейросети уровня плиты. Тысячи
слоёв не превращаются в тысячи независимых печатей. До накопления минимум
десятков разных компоновок основной моделью остаётся физика + ограниченная
NNLS/robust calibration.

После накопления данных сравниваются только в shadow-режиме:

- hierarchical/mixed-effects модель с частичным переносом между режимами;
- gradient boosting по послойным геометрическим признакам и параметрам
  стратегии;
- conformal interval с группировкой по компоновке;
- online residual correction для ETA уже идущей печати;
- change-point/HMM только для диагностики смены режима и повторных попыток.

Нейросеть принимается лишь если chronological grouped validation устойчиво
лучше прозрачной модели и на точке, и на интервале.

## Критерий готовности

Модуль можно считать пригодным для оператора, когда:

1. каждая цифра имеет понятный источник и качество входов;
2. прогноз не включает паузы и повторные попытки;
3. полные циклы слоя реконструируются с учётом floor;
4. известная неполная/неоднозначная геометрия не даёт уверенную точку;
5. CV не разделяет повторы одной плиты между train и holdout;
6. полный `pytest`, Ruff, migration drift и чистый upgrade проходят;
7. реальный отчёт восьми пар воспроизводится одной read-only командой.
